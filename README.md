# Persian Formatter — Pretty Text Viewer

ابزار تمیز و خوانا کردن متن خام (فارسی/انگلیسی): تشخیص عنوان/لیست/کد، رنگ‌آمیزی کد (highlight.js)، جدول مارک‌داون، فرمول ریاضی (KaTeX)، چهار تم (تیره، روشن، «مطالعه» و «مطالعهٔ شب»؛ دو تم مطالعه زمینهٔ گرم، کنتراست حدود ۱۱:۱، قلم وزیرمتن و طول سطر حدود ۶۸ حرف دارند) و چیدمان دو ساید‌بار. هر متن در یک زبانه باز می‌شود و تا وقتی ذخیره نشود فقط پیش‌نویسی در همین مرورگر است. متن‌های ذخیره‌شده را می‌توان در پوشه‌ها مرتب کرد و پوشه را با دیگران به اشتراک گذاشت. همهٔ این کارها بدون ورود هم در دسترس‌اند.

## معماری

- **`index.html`** — رابط فرمت‌کننده.
- **`workspace.js`** — زبانه‌های متن: پیش‌نویس‌ها، ذخیره، همگام‌سازی و حل تداخل.
- **`library.js`، `library.css`** — کتابخانه (پوشه‌ها، جابه‌جایی با کشیدن و رها کردن، اشتراک پوشه) و حساب.
- **`server/`** — API روی Node.js + TypeScript با معماری سه‌لایه:
  - `handlers/` — لایهٔ HTTP (تبدیل request/response).
  - `services/` — منطق کسب‌وکار (اعتبارسنجی، تولید id، شمارش بازدید).
  - `repositories/` — دسترسی به داده (Postgres).
  - بقیه: `domain/` (تایپ‌ها)، `db/` (pool + migration)، `config.ts`، `errors.ts`، `middleware/`.

سرور هم `index.html` را سرو می‌کند و هم این API را:

| Method | Path | کار |
|--------|------|-----|
| `POST` | `/api/shares` | ذخیرهٔ `{ content }` → `{ id, url }` |
| `GET`  | `/api/shares/:id` | خواندن یک share |
| `POST` | `/api/shares/:id/reports` | ثبت گزارش مشکل بیننده روی صفحهٔ اشتراکی، با `{ note? }` اختیاری |
| `GET`  | `/api/reports` | فهرست گزارش‌ها (ادمین)؛ نیاز به هدر `x-admin-token` برابر `ADMIN_TOKEN`. بدون ست بودن `ADMIN_TOKEN` غیرفعال است |
| `GET`  | `/s/:id` | همان SPA؛ کلاینت id را از مسیر می‌خواند و محتوا را fetch می‌کند |
| `GET` | `/api/identity` | ساخت نشست مهمان یا خواندن ایمیل حساب جاری |
| `POST` | `/api/auth/register/options` و `/verify` | ساخت حساب با ایمیل و passkey |
| `POST` | `/api/auth/login/options` و `/verify` | ورود با ایمیل و passkey |
| `POST` | `/api/auth/logout` | خروج |
| `GET` | `/api/library` | فهرست پوشه‌ها (با نقش کاربر) و متن‌ها (بدون بدنه) |
| `GET` | `/api/library/search?q=` | جستجو در عنوان و متن همهٔ متن‌های در دسترس (ي/ك با ی/ک یکی حساب می‌شود)، با بخشی از متن اطراف نتیجه |
| `GET` | `/api/documents/:id/versions` و `/versions/:version` | نسخه‌های قبلی متن (با هر ذخیرهٔ متن یا عنوان، تا ۵۰ نسخه) |
| `GET` | `/api/library/trash` | سطل زباله: متن‌های حذف‌شدهٔ خود کاربر یا پوشه‌هایی که اجازهٔ ویرایش دارد |
| `POST`، `DELETE` | `/api/documents/:id/restore` و `/permanent` | بازیابی از سطل زباله یا حذف همیشگی؛ سطل زباله پس از ۳۰ روز خالی می‌شود |
| `GET`، `PATCH`، `DELETE` | `/api/documents/:id` | خواندن، ویرایش/تغییر نام/انتقال (`version` الزامی) و حذف (`?version=`) |
| `POST` | `/api/documents` | ذخیرهٔ متن تازه `{ title, content, folderId? }` |
| `POST`، `PATCH`، `DELETE` | `/api/folders` و `/api/folders/:id` | ساخت، تغییر نام و حذف پوشه؛ `?documents=delete` متن‌ها را هم حذف می‌کند |
| `DELETE` | `/api/folders/:id/membership` | خروج عضو از پوشهٔ اشتراکی |
| `GET`، `POST`، `DELETE` | `/api/folders/:id/links` | فهرست، ساخت و لغو لینک پوشه؛ فقط مالک |
| `GET`، `DELETE` | `/api/folders/:id/members` | فهرست و حذف اعضا؛ فقط مالک |
| `GET` | `/api/folder-links/:token` | پیش‌نمایش لینک بدون مصرف آن |
| `POST` | `/api/folder-links/:token/join` | پیوستن به پوشه |
| `GET` | `/f/:token` | باز کردن لینک پوشه |

### زبانه‌ها و ذخیره

هر متن یک زبانه است. دکمهٔ «پرشین فرمتر» (کلید `1`) زبانهٔ متن تازه باز می‌کند و «تاریخ» (کلید `2`) مبدل تاریخ را در زبانه‌ای جدا باز می‌کند، یا همان زبانه را اگر باز باشد. متن تازه (Paste، فایل یا صفحهٔ `/s/:id`) اگر زبانهٔ فعلی خالی نباشد در زبانهٔ جدید باز می‌شود. زبانه‌ها در `localStorage` همین مرورگر می‌مانند و تا «ذخیره» (یا `Ctrl/⌘+S`) زده نشود چیزی به سرور فرستاده نمی‌شود. با ذخیره عنوان و پوشه انتخاب می‌شود و زبانه به متن کتابخانه وصل می‌ماند؛ نقطهٔ نارنجی یعنی تغییر ذخیره‌نشده. زبانهٔ تمیز هنگام بازگشت به صفحه از سرور به‌روز می‌شود. اگر متن جای دیگری تغییر کرده باشد (`409 VERSION_CONFLICT`)، کاربر انتخاب می‌کند: نسخهٔ تازه در زبانهٔ دیگر باز شود، نوشته‌اش جایگزین شود، یا جداگانه ذخیره شود. متن فقط‌خواندنی به‌صورت نسخه‌ای در کتابخانهٔ خود کاربر ذخیره می‌شود. با خروج از حساب، زبانه‌های متن‌های ذخیره‌شده بسته می‌شوند و پیش‌نویس‌ها می‌مانند.

ذخیرهٔ مهمان با کوکی نشست انجام می‌شود و تا ۹۰ روز در همان مرورگر در دسترس است. با ورود، متن‌ها، پوشه‌ها و عضویت‌های مهمان به حساب منتقل می‌شوند. ایمیل فقط شناسهٔ حساب است؛ ایمیل تأیید ارسال نمی‌شود. برای ورود دوباره، passkey لازم است. مرورگر و دامنه باید از WebAuthn پشتیبانی کنند (HTTPS یا `localhost`).

### پوشه‌ها و اشتراک

متن بدون پوشه یا داخل یکی از پوشه‌های کاربر است؛ متن داخل پوشه همیشه متعلق به مالک پوشه است. متن را می‌توان با کشیدن و رها کردن یا دکمهٔ انتقال جابه‌جا کرد. انتقال فقط درون کتابخانهٔ یک مالک ممکن است؛ دکمهٔ «کپی» (یا رها کردن متنِ پوشهٔ اشتراکی روی پوشهٔ خودتان) یک نسخهٔ مستقل در کتابخانهٔ شما می‌سازد و اصل متن سر جایش می‌ماند.

مالک برای پوشه لینک می‌سازد: «فقط خواندن»، «ویرایش متن‌ها» (افزودن، ویرایش و حذف متن) یا «مدیریت پوشه» (همچنین تغییر نام و حذف پوشه). هر لینک نام دلخواه، اعتبار ۱، ۷ یا ۳۰ روزه و حالت یک‌نفره یا چندنفره دارد. پیش‌نمایش لینک آن را مصرف نمی‌کند. کسی که لینک را بپذیرد عضو پوشه می‌شود و پوشه در «اشتراکی با من» کتابخانه‌اش می‌ماند؛ دسترسی به حساب (یا نشست مهمان) وابسته است، نه به هدر یا نشانی صفحه. پیوستن دوباره یا تلاش مجدد، لینک یک‌نفره را دوباره مصرف نمی‌کند و لینکی با دسترسی بیشتر عضویت را ارتقا می‌دهد. انقضای لینک فقط ورود افراد تازه را می‌بندد. مالک فهرست لینک‌ها و اعضا را می‌بیند. حذف عضو دسترسی او را برمی‌دارد و لغو لینک دسترسی همهٔ کسانی را که با آن وارد شده‌اند. عضو می‌تواند از پوشه خارج شود. مجوزهای نشستیِ مدل قبلی هنگام migration به عضویت تبدیل می‌شوند.

هر پوشه حداکثر ۵۰ لینک فعال دارد. ساخت لینک برای هر مالک به ۲۰ درخواست در دقیقه، و پیوستن برای هر کاربر به ۶۰ و برای هر لینک به ۱۲۰ درخواست در دقیقه محدود است. پاک‌سازی هنگام راه‌اندازی و هر ساعت، نشست‌ها و چالش‌های منقضی، شمارنده‌های قدیمی و لینک‌هایی را که بیش از ۳۰ روز از انقضایشان گذشته حذف می‌کند (عضویت‌ها می‌مانند).

لینک عمومی یک متن (`/s/:id`) نسخه‌ای مستقل است و با تغییر یا حذف متن یا لغو اشتراک پوشه از بین نمی‌رود.

برای آزمون‌ها:

```bash
npm test --prefix server
npm run typecheck --prefix server
# یک پایگاه دادهٔ آزمایشی؛ آزمون‌ها schema جدا می‌سازند و در پایان پاک می‌کنند.
TEST_DATABASE_URL=postgres://postgres:password@localhost:5432/test npm run test:integration --prefix server
```

## اجرا با Docker Compose (پیشنهادی)

این هم اپ و هم یک Postgres را بالا می‌آورد و جدول‌ها خودکار ساخته می‌شوند:

```bash
docker compose up --build
# http://localhost:8080
```

## اجرای لوکالِ بک‌اند (بدون Docker)

نیاز به یک Postgres در دسترس:

```bash
cd server
npm install
export DATABASE_URL="postgres://postgres:mysecretpassword@localhost:5432/persian_formatter"
export PUBLIC_DIR="$(cd .. && pwd)"   # جایی که index.html هست
npm run dev          # یا: npm run build && npm start
# http://localhost:3000
```

### متغیرهای محیطی

| Env | پیش‌فرض | توضیح |
|-----|---------|-------|
| `PORT` | `3000` | پورت سرور |
| `DATABASE_URL` | `postgres://postgres:mysecretpassword@localhost:5432/persian_formatter` | اتصال Postgres |
| `PUBLIC_DIR` | ریشهٔ مخزن | پوشهٔ شامل `index.html` |
| `MAX_CONTENT_LENGTH` | `200000` | حداکثر طول متن قابل اشتراک |
| `ADMIN_TOKEN` | *(خالی)* | توکن هدر `x-admin-token` برای `GET /api/reports`؛ خالی = endpoint غیرفعال |
| `WEBAUTHN_ORIGIN` | مبدأ درخواست | مبدأ دقیق مرورگر، مانند `https://example.com`؛ برای دیپلوی پشت پراکسی تنظیم شود |
| `WEBAUTHN_RP_ID` | دامنهٔ `WEBAUTHN_ORIGIN` | دامنهٔ ثبت passkey، بدون پروتکل و پورت |

> نکته: اگر می‌خواهی به یک Postgres موجود وصل شوی (مثل همان `localhost:6432`)، فقط `DATABASE_URL` را ست کن و سرویس `postgres` در `docker-compose.yml` را حذف کن.

## دیپلوی (Dokploy)

نوع Application → Build Type = `Dockerfile`. متغیر `DATABASE_URL` را به یک Postgres در دسترس وصل کن و دامنه را به پورت کانتینر `80` متصل کن. برای passkey، `WEBAUTHN_ORIGIN` را با آدرس HTTPS نهایی و `WEBAUTHN_RP_ID` را با نام همان دامنه تنظیم کن.
